Descripción general

Explicación breve del objetivo del proyecto, del problema que resuelve y de sus dos formas principales de uso.

SmartFenix es una aplicación desarrollada con Spring Boot para gestionar clientes, empleados, proyectos y tareas de una forma más organizada. La idea principal del proyecto es reunir en una sola aplicación información que normalmente estaría repartida en distintos sitios, de manera que sea más fácil consultarla, modificarla y comprobar su estado.

El proyecto resuelve el problema de llevar el control de datos empresariales de forma desordenada. En lugar de depender de herramientas separadas, SmartFenix permite centralizar clientes o empresas, empleados internos, proyectos asociados a un cliente y tareas asignadas a proyectos y empleados.

Desde la aplicación, el usuario puede crear registros nuevos, consultar información guardada, modificar datos existentes y eliminar registros cuando sea necesario. La interfaz web con Thymeleaf está pensada para trabajar desde el navegador, mientras que la API REST está pensada para realizar peticiones HTTP desde herramientas como Postman o desde pruebas automáticas.

Arquitectura del sistema

La aplicación sigue una arquitectura por capas para separar responsabilidades y facilitar mantenimiento, pruebas y comprensión del flujo interno.

Capas principales

Domain: contiene las entidades JPA y representa la estructura principal de los datos.

Repository: contiene interfaces que extienden JpaRepository y permiten guardar, buscar, listar y eliminar registros.

Service: concentra la lógica de negocio y evita que el controlador acceda directamente al repositorio.

Controller: recibe peticiones HTTP y devuelve vistas web o respuestas JSON.

Interfaz web y API REST

La aplicación puede usarse desde el navegador o mediante peticiones HTTP, lo que facilita tanto la demostración visual como la verificación técnica.

Interfaz web

La interfaz web permite gestionar clientes, empleados, proyectos y tareas directamente desde el navegador.

  • /
  • /dashboard
  • /clientes
  • /empleados
  • /proyectos
  • /tareas

Cada sección permite listar, crear, editar y eliminar registros.

API REST

La API REST permite trabajar con Postman o con pruebas automáticas como MockMvc.

  • GET consulta datos
  • POST crea datos
  • PUT actualiza datos
  • DELETE elimina datos

Todos los endpoints principales están disponibles bajo /api.

Pruebas unitarias

Las pruebas unitarias revisan la lógica de negocio de forma aislada, sin arrancar toda la aplicación y sin depender de una base de datos real.

Configuración usada

  • JUnit 5
  • Mockito
  • @ExtendWith(MockitoExtension.class)
  • @Mock
  • @InjectMocks

Estas pruebas no usan base de datos real, no usan MySQL, no usan Docker y no usan @SpringBootTest.

Depuración del sistema

La depuración ayuda a entender el flujo interno del programa y a revisar cómo cambian los valores durante la ejecución.

  1. Poner un breakpoint en un método como ClienteService.save(...), ProyectoService.update(...) o EmpleadoService.update(...).
  2. Ejecutar la aplicación o una prueba en modo Debug.
  3. Avanzar paso a paso con Step Over.
  4. Inspeccionar variables y objetos.
  5. Comprobar cómo cambian los datos durante la ejecución.

Incidencias encontradas y soluciones

Durante la revisión de la documentación y de la ejecución del proyecto aparecieron varias incidencias reales que se resolvieron antes de la entrega.

IncidenciaCausaSolución
Documentación antigua contradictoriaExistían documentos con puertos, contraseñas y descripciones de pruebas antiguas.Revisar la documentación y dejar una única versión coherente.
Puerto 8099 ocupadoQuedaba una instancia antigua de Java usando el puerto.Comprobar con lsof -i :8099 y cerrar el proceso.
Confusión entre MySQL real y H2Podía mezclarse la base de datos de la aplicación con la de pruebas.Aclarar que MySQL es para la app real y H2 para integración.
Evitar dependencia de Docker en testsLos tests podían depender del entorno local.Usar Mockito en unitarias y H2 en integración.

Conclusión

Cierre final de la memoria y relación del proyecto con el resultado de aprendizaje trabajado.

Con este proyecto se aprende que verificar una aplicación no consiste solo en mirar si arranca, sino en comprobar de forma ordenada que cada parte funciona como debe. A través de los casos de prueba, las pruebas unitarias, la prueba de integración y la depuración, se puede justificar mejor que el sistema responde correctamente.

Las pruebas ayudan a detectar errores antes de la entrega y permiten trabajar con más seguridad. También es importante separar las pruebas unitarias de las de integración, porque cada una revisa una parte distinta del proyecto.

La depuración con IntelliJ también ayuda mucho a entender el flujo interno del programa, porque permite ver paso a paso qué hace cada método y cómo cambian los datos.

Por todo esto, SmartFenix cumple el resultado de aprendizaje RA3, ya que el proyecto ha sido verificado mediante pruebas diseñadas y ejecutadas sobre el sistema.
